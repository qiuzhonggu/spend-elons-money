# 离线图片与趣味玩法增强设计

## 目标

在保持现有 Vue 3、Pinia 和视觉风格的前提下，完成 10 项增量改进。所有商品图片必须随站点一同部署，不再依赖远程图片服务；新增玩法必须可恢复、可撤销、可测试，并兼容 GitHub Pages 子路径部署。

## 迭代范围

1. 将 110 个商品引用的 105 张唯一远程图片下载并转换为 WebP；重复来源也按商品 ID 复制，最终固定产出 110 个商品文件。
2. 增加资源审计测试，阻止远程 URL、缺失文件和无法识别的图片进入构建。
3. 商品图片加载失败时显示本地占位图和明确的替代文本。
4. 增加「随机豪购」，从当前买得起的商品中随机购买 1 件。
5. 增加「主题采购包」，一次购买预设的跨品类商品组合。
6. 增加「撤销上一笔」，精确回退最近一次购买或批量购买。
7. 增加最近消费历史，展示商品、数量和金额。
8. 增加全品类收藏进度，显示已涉足品类和完成比例。
9. 增加财富顾问动态播报，根据余额、连买次数和品类覆盖生成反馈。
10. 使用 `localStorage` 保存购买数量、消费历史和玩法状态，刷新后继续游戏。

## 架构

- `public/products/` 保存商品图片，JSON 中使用 `/products/<id>.webp` 形式的站点内路径。渲染时通过 Vite 的 `BASE_URL` 解析，以兼容本地根路径和 GitHub Pages 子路径。
- `src/stores/gameplayCore.js` 保存随机候选、采购包报价、收藏进度和顾问播报等纯函数。
- `src/stores/spendingStore.js` 负责动作日志、撤销、持久化与现有购买状态的编排。
- `src/components/PlaygroundPanel.vue` 提供新增玩法入口和消费历史，不改变商品卡片的核心购买路径。
- `src/utils/productImage.js` 统一解析图片路径并提供本地占位图。

## 状态与数据流

每次成功增购或减购都会生成一条动作记录：动作 ID、带正负数量的商品明细、总金额和时间。单买、批量购买、随机豪购、采购包和手动减购都通过同一个动作入口提交。撤销严格反转最近一条动作，因此「买 1 件、减 1 件、再撤销」会恢复为 1 件。持久化层只保存可恢复的原始状态，不保存 `spent`、`remaining` 等派生值。

应用启动时读取带版本号的快照。快照结构无效、版本不匹配或商品已不存在时，回退到全新状态。任何恢复结果都要再次受初始资产上限约束。

## 错误处理

- 图片下载失败时终止本地化过程，不以空文件代替。
- 图片组件触发 `error` 后只切换一次本地占位图，避免错误循环。
- 采购包余额不足时不执行部分购买，并显示具体提示。
- 随机豪购没有可购买商品时保持状态不变并提示。
- `localStorage` 不可用或数据损坏时静默回退，不影响游戏启动。

## 验收标准

- 商品 JSON 中不存在 `http://` 或 `https://` 图片地址。
- 110 个商品均有按商品 ID 命名且可读取的本地 WebP 文件，生产构建后仍可访问。
- 新增纯函数和状态动作均有自动化测试，并经过红灯、绿灯验证。
- 刷新页面后购买状态与历史恢复；撤销后余额和数量准确。
- PC 与移动端布局无横向溢出，新增按钮和文字不重叠。
- `npm test` 与 `npm run build` 均成功，浏览器无控制台错误和失败请求。
- 变更提交并推送到 `main`，GitHub Pages 工作流成功；公开页面及抽检商品图片返回 HTTP 200。
